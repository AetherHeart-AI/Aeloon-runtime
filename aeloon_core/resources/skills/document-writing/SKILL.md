# 专业文档写作

## 建立写作约束

明确文档目的、目标读者、使用场景、所需格式、语气、篇幅和审批要求。区分已确认事实、引用资料、作者判断和待确认信息；不得为了让文档显得完整而虚构事实。

## 先结构后成文

1. 用一句话写出文档希望读者理解或采取的行动。
2. 建立能支撑该目标的标题层级和论证顺序。
3. 将证据、数据和决定放在最相关的章节，避免重复。
4. 起草正文后再编写摘要、标题和目录，以确保它们准确反映内容。

优先使用清晰、具体、可执行的表达。段落只承担一个主要功能；可扫描的信息使用列表或表格，复杂决策说明背景、选项、权衡和结论。

## 格式与引用

- 复用用户提供的模板、样式、页眉页脚、编号和术语。
- 保持标题、正文、表格、图注和引用格式一致。
- 对外部事实和数据保留来源；直接引用应准确且不过度。
- 对需要补充的信息使用明确占位符，例如 `[待确认：审批人]`。
- 交付可编辑文件，并在条件允许时渲染检查分页、断行、表格和目录。

## 审阅

从准确性、完整性、逻辑、语气和版式五个方面检查。核对姓名、日期、数字、单位、交叉引用和附件；删除重复表述、模板残留、内部提示以及无意保留的修订内容。最后列出关键假设和未决事项。

## 交付文件

完成并验证真实文档文件后，只调用一次 `present_files`，一次性声明全部最终交付物。不得声明生成脚本、缓存、模板副本或临时导出文件。最终回复只简要说明已交付内容、关键假设和待确认项，不粘贴生成代码，也不使用本地 Markdown 链接重复交付文件。
